# Papers — Clean Data Encoder

Reference papers on instruction-conditioned embeddings, LLM-based data cleaning, and entity/record matching, collected for the Clean Data Encoder project (prompt-conditioned embeddings for semantic data cleaning and record matching, evaluated against the AddressTable / "Clean Me If You Can" dataset).

## Instruction-conditioned / task-aware embedding models
- **01_INSTRUCTOR_instruction_finetuned_embeddings_2022.pdf** — Su et al., "One Embedder, Any Task: Instruction-Finetuned Text Embeddings" (arXiv:2212.09741, ACL Findings 2023). Introduces prepending a natural-language task instruction before encoding; core mechanism for asymmetric instruction-conditioning.
- **02_E5_Mistral_improving_text_embeddings_LLM_2024.pdf** — Wang et al., "Improving Text Embeddings with Large Language Models" (arXiv:2401.00368, 2024). LLM-based embedder (E5-Mistral) trained on synthetic instruction-following data across many task types including retrieval/matching.

## Entity matching / record linkage benchmarks & techniques
- **03_WDC_Products_entity_matching_benchmark_2023.pdf** — Peeters et al., "WDC Products: A Multi-Dimensional Entity Matching Benchmark" (arXiv:2301.09521, 2023). Real-world noisy product-listing entity matching benchmark.
- **04_Pretrained_Embeddings_Entity_Resolution_VLDB_2023.pdf** — Skoutas et al., "Pre-trained Embeddings for Entity Resolution: An Experimental Analysis" (VLDB 2023). Benchmarks plain pretrained embedding models on entity resolution.
- **05_Heterogeneity_Entity_Matching_Survey_2025.pdf** — "Heterogeneity in Entity Matching: A Survey and Experimental Analysis" (arXiv:2508.08076, 2025). Survey of how matching methods handle format/schema/lexical noise.
- **09_Probabilistic_Record_Linkage_Pretrained_Embeddings_fuzzylink.pdf** — Ornstein, "Probabilistic Record Linkage Using Pretrained Text Embeddings" (Political Analysis, 2026 / `fuzzylink` package). Applied fuzzy record linkage using pretrained embeddings + LLM classifier — closest applied analog to this project's matching goal.

## LLM-based data cleaning
- **06_Data_Cleaning_Using_LLMs_2024.pdf** — Zhang, Huang, Wu (Columbia), "Data Cleaning Using Large Language Models" (arXiv:2410.15547, 2024).
- **07_Towards_Practical_Benchmarking_Data_Cleaning_Authentic_Errors_LLMs_2025.pdf** — "Towards Practical Benchmarking of Data Cleaning Techniques: On Generating Authentic Errors via Large Language Models" (arXiv:2507.10934, 2025). Useful for synthetic noise-injection methodology.

## Target dataset paper
- **08_Clean_Me_If_You_Can_Address_Dataset_2026.pdf** — Ahmadi, Bernhard, Abdelmaksoud, Zecchini, Rabl, Abedjan, "Clean Me If You Can: A Large Collection of Real-World Addresses for Data Cleaning Benchmarking" (arXiv:2606.31983, July 2026). Introduces the AddressTable dataset and benchmarks Horizon, UniClean, HoloClean, Raha/Baran, DataWig, and an LLM-prompting approach (Glock's) — none of them embedding-based, which is the gap this project targets.

## Alternative technique families (for comparison)
- **10_Ditto_Deep_Entity_Matching_PretrainedLM_2020.pdf** — Li et al., "Deep Entity Matching with Pre-Trained Language Models" (arXiv:2004.00584, VLDB 2020). Fine-tunes a PLM (BERT-family) directly as a binary matcher on serialized record pairs — a supervised, non-embedding-space alternative to compare against.
- **11_Sudowoodo_Contrastive_SelfSupervised_DataIntegration_2022.pdf** — Wang et al., "Sudowoodo: Contrastive Self-supervised Learning for Multi-purpose Data Integration and Preparation" (arXiv:2207.04122, ICDE 2023). Learns a shared embedding space via contrastive self-supervised learning across entity matching, data cleaning, and other integration tasks — closest existing embedding-based technique family, though not instruction-conditioned or noise-aware by design.
- **12_Can_Foundation_Models_Wrangle_Your_Data_2022.pdf** — Narayan et al., "Can Foundation Models Wrangle Your Data?" (arXiv:2205.09911, VLDB 2023, Stanford/HazyResearch). Uses zero/few-shot LLM prompting (no fine-tuning, no embeddings) directly for entity matching, data imputation, and error detection — a prompting-only alternative baseline.
- **13_Raha_Configuration_Free_Error_Detection_2019.pdf** — Mahdavi et al., "Raha: A Configuration-Free Error Detection System" (SIGMOD 2019). The original paper behind the Raha detector re-benchmarked in the Clean Me If You Can paper — semi-supervised, feature/classifier-based, no embeddings.
- **14_DataWig_Missing_Value_Imputation_JMLR_2019.pdf** — Biessmann et al., "DataWig: Missing Value Imputation for Tables" (JMLR 2019, Amazon). Original paper for the deep-learning imputation baseline also re-benchmarked in Clean Me If You Can (best correction F1 ~0.29 among non-LLM baselines there).
- Classic non-ML baseline for context (not included as PDF — pre-arXiv era, paywalled): Fellegi & Sunter, "A Theory for Record Linkage" (JASA, 1969). The foundational probabilistic (non-embedding, non-ML) record linkage framework that `fuzzylink`, Raha/Baran-style systems, and most modern record linkage tools still reference or extend.

## Classical / rule-based & statistical data cleaning systems (foundational, pre-deep-learning)
- **15_HoloClean_Holistic_Data_Repairs_2017.pdf** — Rekatsinas et al., "HoloClean: Holistic Data Repairs with Probabilistic Inference" (arXiv:1702.00820, VLDB 2017). Original paper behind the HoloClean baseline re-benchmarked in Clean Me If You Can.
- **16_HoloDetect_FewShot_Error_Detection_2019.pdf** — Heidari et al., "HoloDetect: Few-Shot Learning for Error Detection" (arXiv:1904.02285, SIGMOD 2019). Few-shot error detection using data augmentation, a precursor to Raha-style detectors.
- **17_ActiveClean_Interactive_Data_Cleaning_2016.pdf** — Krishnan et al., "ActiveClean: Interactive Data Cleaning for Statistical Modeling" (VLDB 2016). Human-in-the-loop cleaning prioritized by impact on a downstream ML model.
- **23_NADEEF_Commodity_Data_Cleaning_System_2013.pdf** — Dallachiesa et al., "NADEEF: A Commodity Data Cleaning System" (SIGMOD 2013). Early general-purpose, rule-based cleaning framework combining multiple integrity constraint types.

## Classical / feature-based entity resolution & matching systems
- **18_ZeroER_Entity_Resolution_Zero_Labels_2020.pdf** — Wu et al., "ZeroER: Entity Resolution using Zero Labeled Examples" (arXiv:1908.06049, SIGMOD 2020). Unsupervised generative modeling for matching, no labeled training pairs needed.
- **21_DeepER_Deep_Entity_Resolution_2017.pdf** — Ebraheem et al., "DeepER — Deep Entity Resolution" (arXiv:1710.00597). One of the earliest deep learning approaches to entity resolution, using distributed representations (an early embedding-adjacent method).
- **22_Magellan_Entity_Matching_Management_Systems_2016.pdf** — Konda et al., "Magellan: Toward Building Entity Matching Management Systems" (VLDB 2016). Widely used end-to-end EM system/toolkit (py_entitymatching), a practical feature-engineering + ML-classifier pipeline baseline.
- **26_DeepMatcher_Design_Space_Exploration_2018.pdf** — Mudgal et al., "Deep Learning for Entity Matching: A Design Space Exploration" (SIGMOD 2018). Systematically compares deep learning architectures (RNN, attention, hybrid) for EM — DeepMatcher tool comes from this paper.
- **29_Almost_All_Entity_Resolution** *(paywalled — could not download; cite by reference)* — Binette & Steorts, "(Almost) All of Entity Resolution" (Science Advances, 2022). Broad statistical/methodological survey of entity resolution across disciplines.

## LLM-based entity matching & data preprocessing (newer)
- **19_Using_ChatGPT_for_Entity_Matching_2023.pdf** — Peeters & Bizer, "Using ChatGPT for Entity Matching" (arXiv:2305.03423, ADBIS 2023). Early study of zero/few-shot GPT prompting for EM, precursor to the "Match, Compare, or Select?" line.
- **20_Entity_Matching_using_LLMs_Peeters_2024.pdf** — Peeters, Steiner, Bizer, "Entity Matching using Large Language Models" (arXiv:2310.11244, 2024). Extended study across open and closed LLMs, in-context learning strategies for EM.
- **24_TableGPT_Table_Finetuned_GPT_2024.pdf** — Li et al., "Table-GPT: Table Fine-tuned GPT for Diverse Table Tasks" (Microsoft Research, SIGMOD 2024). Instruction-tunes a GPT model specifically on diverse table tasks (including data cleaning-adjacent tasks) — relevant prior art for "instruction-style conditioning" applied to tabular/text data, though not embedding-based.
- **25_Jellyfish_LLM_Data_Preprocessing_2024.pdf** — Zhang et al., "Jellyfish: A Large Language Model for Data Preprocessing" (arXiv:2312.01678, EMNLP 2024). Instruction-tunes a local LLM specifically for data preprocessing tasks (error detection, correction, matching) — closely related to your instruction-conditioning angle, but applied to generate/correct text directly rather than to condition an embedding space.
- **28_BoostER_LLMs_Entity_Resolution_2024.pdf** — Li, Li, Hao, "BoostER: Leveraging Large Language Models for Enhancing Entity Resolution" (arXiv:2403.06434, WWW 2024 companion). Uses LLMs to boost/refine traditional ER pipelines rather than replace them.
- **29_GPT4_Scrambled_Text_Correction_2023.pdf** — study of GPT-4's ability to correct scrambled/noisy text (arXiv:2311.18805, 2023) — directly relevant to the "can a model see past formatting noise" question your idea is built on, though tested as direct text correction rather than embedding-space conditioning.

## Embedding methodology (general, not domain-specific)
- **27_SentenceBERT_Siamese_Networks_2019.pdf** — Reimers & Gurevych, "Sentence-BERT: Sentence Embeddings using Siamese BERT-Networks" (arXiv:1908.10084, EMNLP 2019). Foundational method for producing comparable sentence embeddings efficiently via siamese/triplet networks — the architectural ancestor of most modern text embedding models including INSTRUCTOR and E5.

## Comparison table — sorted by publication year

| Year | File / Technique | Problem Solved | Dataset(s) Used | Limitation |
|---|---|---|---|---|
| 1969 | Fellegi & Sunter — "A Theory for Record Linkage" *(not downloaded, paywalled)* | Formalized probabilistic decision theory for deciding if two records refer to the same entity | Census/administrative record pairs (original application) | Assumes conditional independence of field comparisons; no notion of semantic content, pure statistical matching; brittle to unmodeled correlation between fields |
| 2013 | 23_NADEEF — Commodity Data Cleaning System | General-purpose rule-based cleaning combining multiple constraint types (FDs, CFDs, dedup rules) in one framework | TPC-H, real-world hospital & business listing datasets | Requires manually authored rules/constraints per dataset; no learning, can't generalize to unseen error types; no semantic understanding of noise |
| 2016 | 17_ActiveClean — Interactive Data Cleaning for Statistical Modeling | Prioritizes which dirty records to clean based on impact on a downstream ML model, minimizing human cleaning effort | UCI datasets (Adult, Airbnb), synthetic dirty data | Needs a human in the loop continuously; optimized for model accuracy, not general-purpose record correctness; not usable for pure data cleaning/matching without a target model |
| 2016 | 22_Magellan — Entity Matching Management System | End-to-end EM pipeline (blocking, feature engineering, classifier training) as a practical toolkit | Standard EM benchmarks (Fodors-Zagat, DBLP-ACM, Abt-Buy, etc.) | Relies on hand-engineered similarity features; brittle to novel formatting noise not captured by chosen features; requires labeled training pairs |
| 2017 | 15_HoloClean — Holistic Data Repairs with Probabilistic Inference | Combines integrity constraints, external data, and statistics into a factor graph for automated repair | Hospital, Food inspection (Chicago), synthetic TPC-H-based benchmarks | Repair quality depends heavily on quality/coverage of integrity constraints and external reference data; weak on free-text/unstructured noise (confirmed by its low ~0.001 correction F1 on the address dataset in this project's target paper) |
| 2017 | 21_DeepER — Deep Entity Resolution | First deep learning approach to EM using distributed word representations instead of hand-crafted features | Standard EM benchmarks (DBLP-ACM, DBLP-Scholar, Cora, etc.) | Uses static (non-contextual) word embeddings (word2vec/GloVe-era); no ability to condition representations on task or noise type; superseded by transformer-based methods |
| 2018 | 26_DeepMatcher — Design Space Exploration for EM | Systematic comparison of deep architectures (RNN, attention, hybrid) for entity matching, establishing best practices | DeepMatcher benchmark suite (structured, textual, dirty EM datasets) | Task-specific trained models, not general-purpose embeddings; dirty-data variant shows all architectures degrade substantially under noise, without a fix |
| 2019 | 13_Raha — Configuration-Free Error Detection | Semi-supervised error detection using ensembled feature vectors + classifier, minimal configuration needed | Hospital, Flights, Beers, Rayyan, and other standard error-detection benchmarks | Only detects errors, doesn't correct them; feature vectors are heuristic-driven, not semantic; needs some labeled examples despite being "configuration-free" |
| 2019 | 14_DataWig — Missing Value Imputation for Tables | Deep learning imputation for missing/incorrect table values, calibrated probability outputs | Synthetic + real tabular datasets (e.g. MovieLens, restaurant data); re-benchmarked on AddressTable (this project's target dataset) | Best correction F1 on AddressTable only ~0.29 — designed for missing values, not for correcting free-text formatting noise; no semantic/embedding-based matching |
| 2019 | 16_HoloDetect — Few-Shot Learning for Error Detection | Error detection via data augmentation to work with very few labeled examples | Hospital, Flights, and other standard SIGMOD-era error-detection benchmarks | Detection-only, no correction; augmentation strategy is rule-based (typos, formatting perturbations) rather than learned semantic robustness |
| 2019 | 27_Sentence-BERT — Siamese BERT Networks | Efficient, comparable sentence embeddings via siamese/triplet network fine-tuning (foundational method, not domain-specific) | STS benchmark, NLI datasets | General-purpose semantic similarity, not tuned for structured record matching or noise robustness; no instruction-conditioning mechanism |
| 2020 | 10_Ditto — Deep Entity Matching with Pre-trained LMs | Fine-tunes BERT-family PLMs directly as binary matchers on serialized record pairs, with data augmentation for robustness | Standard + dirty EM benchmarks (DBLP-ACM, WDC, Abt-Buy, dirty variants) | Supervised, needs labeled pairs per domain; matcher output is binary (match/no-match), not a reusable embedding space; augmentation-based noise robustness is limited to the noise types simulated in training |
| 2020 | 18_ZeroER — Entity Resolution using Zero Labeled Examples | Unsupervised generative modeling for matching without any labeled training pairs | Standard EM benchmarks (Magellan suite: DBLP-ACM, Abt-Buy, etc.) | Assumes a generative mixture model over similarity scores; performance drops on highly heterogeneous or noisy real-world data where the mixture assumption breaks down |
| 2020 | 09_fuzzylink — Probabilistic Record Linkage Using Pretrained Embeddings | Fuzzy record linkage combining pretrained text embeddings with an LLM classifier | Political science entity datasets (e.g. legislator/organization name matching) | Uses plain (non-instruction-conditioned) embeddings; noise robustness comes from the embedding model's inherent generalization, not explicit noise-type prompting; relies on an LLM call per candidate pair, costly at scale |
| 2022 | 01_INSTRUCTOR — Instruction-Finetuned Text Embeddings | One embedding model adapts its vector space per task via a prepended natural-language instruction | MTEB (massive text embedding benchmark, 70+ datasets across 330 tasks) | Instructions are task-descriptive, not noise-descriptive; never evaluated on structured/tabular noisy-vs-clean matching; asymmetric instruction use is possible but untested for this use case |
| 2022 | 12_Can Foundation Models Wrangle Your Data? | Zero/few-shot LLM prompting directly for EM, imputation, and error detection, no fine-tuning or embeddings | Standard EM benchmarks, imputation benchmarks (Restaurant, Buy, etc.) | No embedding space produced (no reusable representation for large-scale matching); costly at scale (LLM call per pair); accuracy sensitive to prompt design |
| 2022 | 11_Sudowoodo — Contrastive Self-Supervised Learning for Data Integration | Learns a shared embedding space via contrastive self-supervised learning, usable across EM, cleaning, and other integration tasks | EM benchmarks (Magellan suite), data cleaning benchmarks | Closest existing embedding-based method to this project, but contrastive pretraining is not instruction-conditioned or explicitly noise-aware; can't be steered per-query with a noise description |
| 2023 | 03_WDC Products — Multi-Dimensional EM Benchmark | Provides a difficulty-graded, real-world noisy e-commerce entity matching benchmark | WDC Products (product offer corpus, web-scraped) | Benchmark paper, not a technique — establishes evaluation difficulty tiers but doesn't propose a noise-robust matching method itself |
| 2023 | 04_Pre-trained Embeddings for Entity Resolution (VLDB) | Benchmarks off-the-shelf pretrained embedding models (no instruction-conditioning) on entity resolution | Magellan EM benchmark suite | Plain embeddings show inconsistent robustness to formatting/lexical noise across datasets; no mechanism proposed to improve it (motivates instruction-conditioning as a fix) |
| 2023 | 19_Using ChatGPT for Entity Matching | Early study of zero/few-shot GPT prompting for EM | WDC Products, standard Magellan EM benchmarks | Prompting-only, no embeddings; performance and cost scale poorly to large-scale matching; results sensitive to prompt phrasing |
| 2023 | 29_GPT-4 Scrambled Text Correction study | Evaluates GPT-4's ability to reconstruct/correct scrambled or noisy text | Constructed scrambled-text test sets (character/word-order perturbations) | Tests direct text correction, not embedding-space matching; doesn't address record-to-canonical matching, only text reconstruction in isolation |
| 2024 | 02_E5-Mistral — Improving Text Embeddings with LLMs | LLM-based embedder trained on synthetic instruction-following data across many task types including retrieval/matching | MTEB, BEIR (retrieval benchmark) | Synthetic training data covers general task types, not specifically noise-type-conditioned cleaning instructions; largest model variant is expensive to run at scale |
| 2024 | 06_Data Cleaning Using LLMs (Columbia) | Uses LLMs to resolve inconsistent value representations in tables | Real-world and synthetic tabular datasets with representation inconsistencies | Focused narrowly on value-representation inconsistency, not broader noise types (spacing/tabs/apostrophes); direct LLM correction, not embedding-based |
| 2024 | 20_Entity Matching using Large Language Models | Extended study of in-context learning strategies for EM across open/closed LLMs | WDC Products, Magellan EM benchmark suite | No embeddings produced; in-context example selection is a manual/heuristic design choice; costly per-pair LLM inference |
| 2024 | 24_Table-GPT — Table Fine-tuned GPT | Instruction-tunes a GPT model on diverse table tasks (including cleaning-adjacent tasks) | Synthesized diverse table-task instruction dataset + table benchmarks | Instruction-tuning is on table *tasks* broadly, not specifically noise-type description for embedding conditioning; outputs are generated text/tables, not embeddings |
| 2024 | 25_Jellyfish — LLM for Data Preprocessing | Instruction-tunes a local LLM specifically for data preprocessing (error detection, correction, matching) | Standard data preprocessing benchmarks (error detection, EM, data imputation task sets) | Generates/corrects text directly rather than producing a reusable embedding space; instruction-tuning targets general preprocessing tasks, not explicit noise-type descriptions |
| 2024 | 28_BoostER — Leveraging LLMs for Enhancing Entity Resolution | Uses LLMs to boost/refine traditional ER pipelines rather than replace them | Standard EM/ER benchmarks | Hybrid approach still depends on a traditional ER pipeline's quality; LLM calls add cost; not a standalone embedding-based solution |
| 2025 | 05_Heterogeneity in Entity Matching (Survey) | Surveys how matching methods handle format/schema/lexical heterogeneity | Multiple EM benchmarks (survey/meta-analysis) | Survey paper — synthesizes findings but doesn't propose a new noise-robust technique itself |
| 2025 | 07_Towards Practical Benchmarking of Data Cleaning (Authentic Errors via LLMs) | Generates authentic-looking synthetic errors via LLMs for more realistic data-cleaning benchmarks | Newly generated synthetic-error datasets (LLM-injected errors on top of clean base data) | Focused on benchmark *construction* methodology, not a cleaning technique; doesn't evaluate embedding-based approaches |
| 2026 | 08_Clean Me If You Can — AddressTable dataset paper | Introduces a large real-world address dataset and benchmarks 6 cleaning techniques (rules, stats, classifiers, imputation, LLM prompting) | AddressTable (this project's target dataset) | None of the 6 benchmarked techniques are embedding-based; best correction F1 only ~0.29 (DataWig, Glock's) — the exact gap this project's approach targets |
| 2026 | 09_fuzzylink (Political Analysis publication) | Applied probabilistic record linkage using pretrained embeddings + LLM classifier | Political science entity/legislator datasets | Same limitations as the 2020 preprint version above — plain embeddings, no noise-type instruction-conditioning |

## Key takeaway
No existing paper combines noise-type-descriptive instructions + asymmetric query-side prompting + clean canonical-side embeddings for record matching/cleaning. INSTRUCTOR and E5-Mistral provide the mechanism; fuzzylink and the Clean Me If You Can baselines provide the closest applied comparisons and the dataset to beat (best correction F1 so far: ~0.29, from DataWig and Glock's).

Full technique landscape now covered, oldest to newest:
1. **Rule/constraint-based** (1990s–2013 era methodology, tooled up through the 2010s): NADEEF, Horizon, UniClean — functional dependencies and integrity constraints, no learning.
2. **Statistical/probabilistic** (1969 Fellegi-Sunter onward): HoloClean, Fellegi-Sunter-descended tools (Splink, fuzzylink) — factor graphs, probabilistic matching.
3. **Feature-engineered ML classifiers** (2013–2020): Raha/Baran, Magellan/py_entitymatching, ZeroER — hand-crafted features + classical or generative classifiers.
4. **Deep learning, pre-embedding-model era** (2017–2019): DeepER, DeepMatcher, HoloDetect, DataWig — early neural approaches, RNN/attention architectures, task-specific representations (not general-purpose embeddings).
5. **Supervised PLM fine-tuning** (2019–2020): Sentence-BERT (general method), Ditto (BERT fine-tuned specifically as a matcher).
6. **Contrastive self-supervised embeddings** (2022): Sudowoodo — the closest existing embedding-based technique family to this project, but not instruction- or noise-conditioned.
7. **Instruction-conditioned / task-aware embeddings** (2022–2024): INSTRUCTOR, E5-Mistral — the mechanism this project's approach is built on, not yet applied to noise-type-aware data cleaning.
8. **LLM prompting / instruction-tuning for data tasks** (2023–2024): Using ChatGPT for Entity Matching, Entity Matching using LLMs, Can Foundation Models Wrangle Your Data?, Table-GPT, Jellyfish, BoostER, GPT-4 scrambled text correction — direct text-in/text-out LLM approaches (no intermediate embedding space for matching).
9. **The gap this project targets**: nothing in families 6–8 combines an explicit noise-type instruction, asymmetric application (noisy query only), and a shared embedding space for matching against a clean canonical side.
